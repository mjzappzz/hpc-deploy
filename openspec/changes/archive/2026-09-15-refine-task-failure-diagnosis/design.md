## Context

现有诊断器以任务状态、报告摘要、`error_message` 和全文日志的关键词规则生成单一 `conclusion`。规则可识别若干已知故障，但首个命中可能掩盖最后的致命事件；无报告任务中的明确平台错误也可能退回到泛化说明。报告摘要缓存和历史列表复用该单一原因，极限压测的整体错误还会遮蔽子模块证据。

## Goals / Non-Goals

**Goals:**

- 让失败任务的默认说明优先展示直接、可验证的失败事实和下一步动作。
- 明确区分已确认事实、责任边界与待核查假设，避免将推测作为根因。
- 为受控 Linux 压测、极限压测和平台 runner 建立稳定、可回收的诊断事件路径。
- 保持旧任务和通用脚本的诊断可用，并避免诊断输出泄露敏感内容。

**Non-Goals:**

- 不在运行时使用 LLM 或外部服务裁定根因。
- 不改变任务调度、压测参数、报告 PASS/FAIL 或最终状态优先级。
- 不要求第三方或用户上传的脚本遵循新的诊断事件契约。
- 不承诺在证据不足时自动确定服务器重启、硬件故障或网络根因。

## Decisions

### 采用分层诊断记录，而非单一失败字符串

诊断聚合结果新增稳定的分层字段：`failure_phase`、`confirmed_facts`、`attribution`、`confidence`、`evidence`、`investigation_hints` 和 `next_actions`。现有 `conclusion` 与 `failure_reason` 保留为兼容性摘要，但只由最高置信度的已确认事实生成；没有直接事实时使用“原因待核查”的保守摘要。

替代方案是继续扩展关键词和固定话术。该方案不能表达证据强度，也无法避免推测性结论，故不采用。

### 定义事件来源优先级和冲突处理

诊断聚合按以下顺序收集和比较事件：

1. 平台已确认事件：取消、认证/连接、上传、回收和 runner 状态收口。
2. 受控脚本或极限编排器输出的结构化阶段与终态事件。
3. 报告中的明确验证失败原因及子模块结果。
4. 任务 `error_message` 中的直接失败事实。
5. 终态附近的原始日志签名回退。

同一层级发生冲突时，保留多个事实并说明冲突；低优先级事件不得覆盖高优先级证据。通用汇总消息（例如“GPU or CPU/memory stress failed”）只可描述整体状态，不可作为具体根因。

### 受控压测输出可回收的诊断事件

GPU、CPU/内存、磁盘和极限压测在依赖检查、实际压测、报告生成和退出时输出版本化诊断事件。事件包含阶段、稳定失败码、结果、简短消息、退出码和经脱敏的证据标识；终态事件同时写入可回收的任务诊断文件。平台 runner 解析事件并在 artifact 收集后将其纳入摘要缓存。

替代方案是只解析自由文本日志。该方案继续受语言、工具版本和历史行干扰，且无法稳定定位最后一个致命阶段，故仅作为旧任务和非受控脚本的兼容回退。

### 原始日志回退只分析终态上下文

没有结构化事件时，诊断器先采纳明确的任务错误，再在终态错误附近的有限日志窗口中运行兼容规则。回退结果的 `confidence` 为 `inferred` 或 `unknown`，前端必须使用“待核查”语义；不能由普通出现的 `nvidia-smi`、网络重试或历史日志单独形成确定根因。

### 极限压测按整体、模块和编排三个层次输出

极限压测摘要保留整体最终状态，但将 GPU、CPU/内存与同步/处置事件分别写入诊断记录。前端先展示整体结论，再展示每个失败层的已确认事实；没有模块证据时明确标注该模块原因待核查。

### 前端采用“结论先行、证据可展开”布局

历史列表和任务卡片使用短摘要：失败阶段、已确认事实或“原因待核查”。诊断详情依次展示最终状态、已确认事实、直接证据、待核查项和下一步动作；原始日志继续通过现有下载和日志面板提供。

## Risks / Trade-offs

- [旧任务没有结构化事件] → 继续保留兼容回退，并显式标记推断/待核查，不回填虚假的确定根因。
- [脚本事件实现不一致] → 先定义版本化契约并为每类受控脚本增加契约测试；解析未知版本时降级为原始日志回退。
- [诊断字段增加前后端耦合] → 保持现有字段和 API 可读，新增字段可选；先由后端提供兼容摘要。
- [原始证据含敏感内容] → 复用现有敏感字段过滤，并禁止把完整命令、私钥、密码、Token 或未过滤环境变量写入结构化事件。
- [缓存使历史说明滞后] → 使用诊断版本标识触发摘要重算；重算失败时保留旧摘要并在后台重试。

## Migration Plan

1. 引入诊断记录和事件解析，但保留现有诊断 API 字段与历史日志回退。
2. 先接入平台 runner 和极限压测，再接入 GPU、CPU/内存、磁盘脚本。
3. 为已完成历史任务重算报告摘要；无法得出直接事实的任务显示保守兼容结果。
4. 发布后抽样对比新旧诊断，确认已确认事实均有对应证据，随后再将新布局作为默认展示。
5. 如出现诊断聚合回归，回退前端新布局和新摘要版本；任务执行、报告及原始日志不受影响。
