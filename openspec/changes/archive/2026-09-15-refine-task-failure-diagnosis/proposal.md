## Why

当前任务故障说明以关键词首个命中和固定话术为主，可能把汇总失败、历史日志或待核查假设展示为确定根因；同时，日志和任务错误中已存在的明确失败信息又可能被降级为泛化文案。运维人员需要先直观看到可信的直接原因和下一步动作，而不是在详情中辨别推测与事实。

## What Changes

- 将故障说明拆分为已确认事实、失败阶段、归因边界、原始证据、待核查项和建议动作。
- 让任务错误、结构化脚本阶段/失败事件、报告明确 FAIL 原因和平台执行事件按证据强度聚合，而非按全文关键词的首个命中定论。
- 为可控压测脚本和 runner 定义可回收的结构化诊断事件，优先覆盖取消、SSH、依赖准备、启动前失败、报告 FAIL 和 artifact 回收失败。
- 按子模块展示极限压测的 GPU、CPU/内存和编排结果，整体汇总失败不再代替具体子模块原因。
- 更新任务历史与诊断详情，使默认故障说明简洁、可执行，并在证据不足时明确标注“待核查”。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `task-results-observability`: 任务与批次的诊断结果必须区分已确认事实、推断和证据，并为故障处置提供可执行信息。
- `stress-validation`: Linux 压测和极限压测必须输出可被平台回收与解析的失败阶段和结果证据。

## Impact

- 影响后端诊断聚合、报告摘要缓存、任务序列化和诊断 API 返回结构。
- 影响 Linux 压测脚本、极限压测编排结果和 artifact 回收内容。
- 影响任务历史卡片、详情页、批次详情和诊断弹窗；历史任务继续通过兼容回退展示。
- 不改变任务执行语义、压测阈值、最终 PASS/FAIL 状态规则或管理员权限边界。
