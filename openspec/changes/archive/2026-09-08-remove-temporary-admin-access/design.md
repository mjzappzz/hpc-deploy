## Context

当前管理员确认流程除密码验证外，保留一条由环境控制的临时无密码授权路径；它涉及前端隐藏交互、认证 API、一次性令牌、Cookie 与受保护端点的令牌解析。变更动机见 `proposal.md`。

## Goals / Non-Goals

**Goals:**

- 使管理员密码成为签发管理员会话的唯一授权前提。
- 移除无密码路径的全部可达入口与专用状态，防止未来环境配置重新启用。
- 保留现有基于密码的管理员时长、标签页绑定、Cookie 安全属性和登出体验。

**Non-Goals:**

- 不变更管理员密码策略、登录时长选项或受保护业务端点。
- 不引入新的身份提供方、多用户角色模型或恢复口令机制。

## Decisions

- 完整删除临时授权 API、前端调用、环境开关和一次性令牌支持，而非仅将开关默认设为关闭。默认关闭仍保留误配置或开发环境绕过的风险。
- 令牌校验仅接受常规 `admin` 作用域和常规管理员 Cookie/Header；删除一次性 Cookie 的签发、消费和登出清理。
- 以 API 和令牌层回归测试证明无法无密码授权，并以源代码/前端测试确保隐藏交互与调用不存在。

## Risks / Trade-offs

- [依赖旧临时入口的开发调试流程失效] → 使用正常管理员密码和短时会话完成测试；不再保留隐藏绕过方式。
- [遗留浏览器持有旧一次性 Cookie] → 发布后的后端不接受该 Cookie；浏览器将被要求走正常密码验证。

## Migration Plan

1. 先添加验证无密码路径不可用的测试，并确认现状失败。
2. 移除前后端临时授权实现及相关配置。
3. 运行前后端认证回归、类型检查和生产构建。
4. 按既有部署流程发布；后端重启后旧临时授权即失效。若需回滚，恢复前一版本代码与服务，但仅在明确接受恢复该安全风险时执行。
