## Context

当前后端已经通过 artifacts 路径获取所在文件系统的容量，并统计产物与 SQLite 数据库大小；前端通过 summary API 展示简短文字。现有模型没有设备、挂载点、检查路径或分类明细，因此 UI 无法解释分区已用空间。详见 `proposal.md` 和 `runtime-data-lifecycle` 增量规格。

## Goals / Non-Goals

**Goals:**

- 在现有 `/api/dashboard/summary` 上扩展一个向后兼容的 storage 结构。
- 对固定的 HPCDeploy 路径做可解释、非重叠的分类统计，并返回每个路径的检查状态。
- 从实际挂载信息返回设备和挂载点，令容量数值可以被定位和复核。
- 用单个高优先级 Dashboard 卡片同时承载容量图、数字摘要、分类明细、路径信息和异常状态。
- 让缺失、权限不足和统计失败在 API/UI 中可见，并保留现有容量阈值与任务阻断逻辑。

**Non-Goals:**

- 不改变清理、备份、归档、任务状态判定或任务提交策略。
- 不提供任意路径浏览器，不递归扫描整个宿主机文件系统。
- 不引入三维磁盘渲染或新的图表依赖；首版使用现有前端能力绘制轻量环形/圆盘容量图。

## Decisions

### 1. 扩展现有 summary contract，而不是新增轮询接口

在 `StorageStats` 中增加 `usage_percent`、`device`、`mountpoint`、`inspected_paths` 和 `breakdown` 等字段，新增字段允许为未知，保留现有容量、清理和状态字段。这样既保持现有消费者兼容，也保证首屏容量信息与服务器/任务摘要来自同一次刷新。单独新增接口会造成刷新时序不一致，故不采用。

### 2. 使用固定目录白名单和非重叠计算规则

后端定义有限的 HPCDeploy 检查项：任务产物、SQLite 数据库、SQLite 备份、GPU 驱动库、backend/data 其余数据、项目/运行时文件。每个检查项携带展示名、实际路径、字节数和状态；父目录统计在扣除已单列子目录后才计入“其余数据”。分区“其他占用”作为文件系统已用空间减去所有可计算的项目分类之和，并在结果可能不完整时标记为估算/未知。

这种方式能解释当前项目相关占用，同时避免把同一文件计入多个分类；全盘递归扫描虽然更精确但成本和权限风险更高，且超出本次运维看板范围。

### 3. 从挂载信息解析设备和挂载点

以容量基准路径（当前为 artifacts 路径）解析其所在挂载点，并通过系统挂载信息获取设备和规范化挂载路径；解析失败时保留容量统计并将设备/挂载点标为未知。路径必须经过后端固定配置生成，不使用客户端传入值拼接命令或路径。

### 4. 前端采用可访问的轻量容量图

容量图以已用百分比驱动环形 SVG/CSS 表示，中心显示使用率，旁边显示总/已用/可用数字；下方使用颜色稳定的分类图例和实际路径行。颜色、文字和状态标签共同表达信息，不依赖颜色单独传达含义。`unknown`、`warning`、`blocked`、部分扫描失败分别提供明确状态文案和降级布局。

### 5. 调整首屏层级但保留完整统计

容量卡置于刷新控件之后、普通汇总卡之前。服务器统计压缩为在线/离线等连接态，运行中/排队任务保持醒目；任务结果不删除，移动至近期完成任务或较低优先级区域。这样不损失信息，只优化故障排查时的阅读顺序。

## Risks / Trade-offs

- [路径扫描耗时] → 只扫描固定目录、复用已有产物统计并限制单次 summary 扫描范围；接口异常时返回部分结果和状态，不阻塞 Dashboard 其他统计。
- [权限或路径不存在] → 每项返回 `available`/`unavailable`/`partial` 状态和错误原因摘要，前端不把失败项伪装成 `0 B`。
- [“分区其他占用”不是 HPCDeploy 归因] → 明确标注为分区范围差额，并展示分类统计覆盖范围，避免运维误认为系统已定位全部来源。
- [挂载解析依赖主机信息] → 解析失败仅降级设备/挂载点字段，不影响已有 free/used 阈值判断。
- [旧客户端字段缺失] → 前端对新增字段使用能力检测和未知态；后端保留旧字段，便于滚动发布与回滚。

## Migration Plan

1. 先补充后端模型、统计逻辑和 API 测试，再补充前端类型、容量卡布局和回归测试。
2. 在测试环境验证固定路径、权限不足、挂载解析失败和 `unknown` 状态，再按现有项目发布流程发布。
3. 发布后观察 summary 响应、Dashboard 控制台错误和容量分类是否与 `df`/`du` 抽查一致。
4. 若出现问题，回滚前后端版本即可；新增字段为可选，不需要数据库迁移，也不改变清理数据。
