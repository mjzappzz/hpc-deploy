## Why

当前“控制器空间”只展示可用空间、产物占用和 SQLite 占用，无法说明总容量、已用比例、实际设备/挂载点以及其余空间由什么组成。运维人员因此难以判断检查范围、清理收益和容量风险；现在需要把这块信息提升为控制台的核心运行态信息。

## What Changes

- 将控制器空间卡片提升到 Dashboard 顶部，置于刷新/自动刷新区域之后、普通统计卡片之前。
- 增加容量可视化，直观展示总空间、已用空间、可用空间和使用率，并保留容量预警/阻断状态。
- 展示实际检查的文件系统设备、挂载点和 HPCDeploy 检查路径，避免“可用空间”脱离路径语境。
- 按已知 HPCDeploy 目录展示空间构成：任务产物、SQLite 数据库、SQLite 备份、GPU 驱动库、其他 HPCDeploy 数据、项目/运行时文件，以及无法归入已知目录的分区其他占用。
- 调整首屏信息层级：保留在线/离线服务器和运行中/排队任务等运维重点，将任务结果摘要下移到近期完成任务区域，减少首屏低优先级信息。
- 保持现有容量阈值、清理行为和任务执行行为不变；仅补充可观察信息和展示层级。无可靠容量数据时继续显示未知态，不将其误报为 0 或正常。

## Capabilities

### New Capabilities

无。本次能力属于现有运行数据生命周期能力的扩展。

### Modified Capabilities

- `runtime-data-lifecycle`: 扩展控制器空间状态的可观测字段、目录分类和 Dashboard 信息层级要求。

## Impact

- 后端 Dashboard storage 统计模型和 summary API：增加文件系统元数据、检查路径和分类占用信息，保持现有字段兼容。
- 后端已知目录扫描逻辑：仅检查 HPCDeploy 明确目录，不进行任意全盘递归扫描；需要处理路径不存在、权限不足和统计不完整等边界。
- 前端 Dashboard 类型、格式化逻辑和布局：新增容量图、分类图例、路径/设备信息及未知/失败状态展示。
- 前后端单元测试、Dashboard 回归测试及运行数据生命周期文档/进度记录。
- 不新增外部依赖，不改变归档、清理、任务状态判定或部署流程。
