## Context

现有 `AppCritters.vue` 通过 `IntersectionObserver` 和 `MutationObserver` 向通用卡片直接注入随机煤球 DOM。它限制全局数量，但每卡只允许一只，使双煤球对话、邻近和间距逻辑不可达；随机名称、短生命周期和高频发言也更接近彩蛋而非稳定陪伴。设计规范要求不遮挡操作并尊重减少动效。

## Goals / Non-Goals

**Goals:**

- 用一只固定名称“煤球”形成可识别、全局常驻但低打扰的陪伴体验。
- 将投放和发言建立在应用级安全悬浮位、页面上下文和显式任务终态事件上，而非猜测用户状态。
- 默认持续显示煤球，不提供正常、安静、关闭偏好；减少动效或卸载后无残留资源。
- 用可测试的 Vue 状态与 CSS 表现替换不可达的随机角色逻辑。

**Non-Goals:**

- 不提供聊天机器人、自然语言输入、心理状态评估、成就系统或用户画像。
- 不新增后端 API、数据库、权限、遥测或任务调度逻辑。
- 不改变错误、告警、管理员确认和任务终态的业务呈现。

## Decisions

### 1. 单煤球状态机替代随机生命周期

煤球只存在一个逻辑实例，状态为 `hidden`、`entering`、`watching`、`responding`、`leaving`。宿主可见时以探头进入并长期安静值守；明确任务节点、悬停或触屏轻触才触发短暂回应；宿主离开视口时退出并在冷却后迁移。

选择该方案是为了让角色连续可辨，并移除“固定时间后换一只”的随机感。未选择保留两只角色和对话：现有每卡一只的边界与专业控制台的低干扰要求都不支持它。

### 2. 应用级安全悬浮位替代业务卡片宿主

煤球挂载于根应用内容区的安全悬浮容器，普通路由切换时保持同一个实例；桌面默认停靠内容区右下角，窄视口缩小并上移。它不再依赖业务卡片宿主，也不扫描通用卡片。

当弹窗、抽屉、通知、管理员确认、危险操作、错误或告警可见时，煤球留在安全悬浮位但收起气泡、不可抢焦点且不遮挡交互区。选择此方案是为了让煤球在用户视线所及的普通页面持续陪伴，同时不介入高风险操作。未选择继续绑定业务卡片：该方案会让路由覆盖不完整，并把陪伴可见性误绑定到卡片布局。

### 3. 上下文只来自页面与显式任务事件

提供前端只读陪伴上下文：路由/页面类型、全局安全状态，以及任务创建、运行、成功、失败、取消、恢复等页面已经确认的事件。事件必须携带终态；只有 `SUCCESS` 允许触发收尾文案，`FAILED` 与 `CANCELED` 只令煤球静默。文案选择器只消费这些事实与用户陪伴模式；不读取停留时长、点击频率或个人信息。

选择显式事件而非自动分析 DOM 文本或用户行为，以保持反馈可预测、可审计且不造成被窥探感。

### 4. 默认陪伴和低频文案策略

煤球默认在普通路由持续陪伴，在进入、明确任务节点和用户主动交互时低频发言；减少动效时不创建实例。文案按值守、收尾、轻幽默和静默分类，删除把压力指向操作者、过度心理化或在故障时开玩笑的文案。

选择去配置化是因为煤球已被定义为持续陪伴，而顶栏选择器会分散控制台注意力。未选择会话分析和云端设置，以避免隐私与权限扩张。

### 5. 毛绒视觉、Vue 受控渲染与可清理资源

煤球本体、气泡和状态样式使用 Vue 模板与 CSS 状态类渲染；视觉采用蓬松圆脑袋、多层黑灰渐变、两只清晰短脚和轻量呼吸动效，桌面默认约 26px。毛边只围绕头部，不得在脚下形成连续的黑色扩散层。保留必要的安全区域观察，但由组件生命周期统一注册和释放。所有超时、观察器和悬浮位样式修改均必须可恢复。触屏以轻触代替悬停，气泡在无法取得安全空间时不显示。

选择受控渲染可使投放、状态和清理可测试。未选择继续拼接 `innerHTML` 与覆写元素 `remove()`，因为其样式恢复、资源跟踪和测试边界不清晰。

## Risks / Trade-offs

- [悬浮位遮挡窄视口操作] → 按可用视口选择桌面/窄视口位置；无法取得安全空间时只保留本体并收起气泡。
- [任务事件未携带终态] → 退回安静值守，不猜测任务状态，不触发收尾文案。
- [气泡在窄视口遮挡内容] → 先检测安全空间；无空间时只保留煤球本体。
- [本地存储不可用或值非法] → 回退正常陪伴，并不阻塞控制台。
- [减少动效切换后资源残留] → 状态机进入 `hidden` 并统一停止计时器和观察器；为此建立回归测试。

## Migration Plan

1. 先以回归测试固定单实例、全局安全悬浮、偏好、减少动效、终态语义和卸载清理行为。
2. 替换卡片宿主集成为根应用安全悬浮容器，恢复毛绒煤球造型，删除随机名字、双煤球对话和不可达辅助逻辑。
3. 更新趣味设计规范和文案池，构建前端并做跨路由、终态和窄视口浏览器验证。
4. 仅发布前端静态产物；若出现布局或可访问性问题，回滚为当前已发布的前端构建。
