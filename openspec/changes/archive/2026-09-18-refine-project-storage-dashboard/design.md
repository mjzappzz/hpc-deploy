## Context

当前 Dashboard storage 使用 `shutil.disk_usage(ARTIFACTS_DIR)` 计算整个文件系统的比例，并自行维护少量目录分类；系统设置则已经维护一套本地运行路径清单。详见 `proposal.md` 和 `runtime-data-lifecycle` 规格增量。

## Goals / Non-Goals

**Goals:**

- 让 Dashboard 与系统设置共用同一套本地路径定义，避免两个页面统计范围漂移。
- 以本地项目模块总量作为圆盘分母，并保证模块路径互不重复。
- 同时返回字节数、文件数、路径、存在性和扫描状态，支持准确的未知态。
- 保留设备/挂载点作为上下文信息，不让整盘容量污染项目占用图。
- 用轻量分段圆盘和模块明细表达占用，运行状态改为紧凑摘要。

**Non-Goals:**

- 不统计远端服务器目录，不扫描项目目录之外的系统路径。
- 不改变自动清理范围、容量阻断阈值或任务执行状态。
- 不新增数据库表或外部存储依赖。

## Decisions

### 1. 建立共享的本地运行路径清单

将系统设置当前的本地路径定义抽成后端共享清单，Dashboard 和系统设置都从该清单生成展示数据。清单明确标注本地/远端、文件/目录、模块 key 和排除关系；远端项只在系统设置中说明，不进入 Dashboard 项目占用。

直接在 Dashboard 再复制一份路径常量实现简单，但以后新增目录容易漏改，因此不采用。

### 2. 用模块总量而不是文件系统容量驱动圆盘

后端对每个本地模块统计逻辑文件大小和文件数，过滤 symlink 并记录不可读项。项目总占用为可计算本地模块之和；每个模块百分比为 `module_bytes / project_bytes`。项目总量为零或存在无法统计模块时，UI 显示未知/不完整提示，不能把整盘 `used_bytes` 当作项目总量。

现有整盘 `total/free/used` 和设备信息可继续作为容量风险及定位字段返回，但仅用于辅助信息和既有 warning/blocked 逻辑。

### 3. 保证分类不重叠

数据库文件、备份、产物、GPU 驱动库、临时驱动、keys、MPI 脚本、压测脚本和 Apptainer 目录作为独立模块；“其他项目运行文件”扫描项目根目录时排除 `backend/data` 及所有已列出的本地根目录。模块结果按清单顺序返回，便于前端颜色和文案稳定。

### 4. 前端展示采用分段圆盘 + 明细表

使用 SVG 环形分段图，圆心显示“项目总占用”，图例/明细显示模块大小、文件数、百分比和路径。每个模块使用文字标签和大小信息，不依赖颜色传递状态；模块缺失或扫描异常时显示状态标签。设备和挂载点放在卡片底部作为“所在文件系统”上下文。

### 5. 合并重复的服务器/任务摘要

移除独立的大型“服务器”和“任务运行”卡片，将在线/离线、运行中/等待中/取消中放入 Dashboard 运行状态条和“运行中任务”标题区。近期完成任务表继续保留成功/失败/取消结果，避免丢失历史结果。

## Risks / Trade-offs

- [项目目录包含大型运行资产] → 仅扫描共享清单覆盖的本地目录，并缓存或复用同一刷新周期结果，避免每 5 秒无边界扫描。
- [逻辑大小与磁盘块占用不同] → 页面文案明确标注“项目文件占用”，系统文件系统容量仍单独显示为上下文，不混合两个口径。
- [新增本地路径未加入清单] → 以共享清单作为唯一来源，并为未知的项目剩余文件保留“其他项目运行文件”分类。
- [权限或路径不存在] → 返回模块状态和错误摘要，保留可用模块；圆盘在数据不完整时不显示伪造精确比例。
- [旧 API 消费者缺少新字段] → 新字段保持可选/向后兼容，前端对旧 summary 使用未知态降级。

## Migration Plan

1. 先补充共享路径清单、统计单元测试和 summary contract 测试。
2. 将系统设置与 Dashboard 接入共享清单，完成前端圆盘和运行状态条，再运行前后端测试与构建。
3. 在测试环境用系统设置明细、`du` 和已知文件抽样核对项目总量与各模块合计。
4. 发布后若展示异常，回滚前后端版本；无数据库迁移，旧的整盘容量字段继续兼容。
