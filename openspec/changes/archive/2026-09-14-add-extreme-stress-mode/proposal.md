## Why

现有 Linux 压测仅支持 GPU、CPU/内存与磁盘的串行组合，无法在同一有效压力窗口内验证 GPU 与主机 CPU/内存的耦合稳定性。运维人员需要一个不包含磁盘 I/O、可自动准备依赖、并能作为单一结论管理的极限压测模式。

## What Changes

- 在任务下发的服务器压测中增加与常规压测互斥的“极限压测”执行模式；固定运行 GPU 与 CPU/内存，且不创建磁盘任务。
- 新增一个原子极限压测编排任务：自动完成 GPU 与 CPU/内存依赖准备，等待两侧 ready 后通过共享屏障同步启动实际压力负载。
- 极限模式提高主机内存安全保留线至物理内存的 15%；任一模块在准备、运行或同步校验中失败、超时或被取消时，终止另一模块并使整体失败或取消。
- 生成总报告以及可独立下载的 GPU、CPU/内存子报告和原始日志；仅两模块均 PASS 且启动偏差满足阈值时，整体通过。
- 历史任务将极限压测显示为不可拆分的单一任务，并在详情中展示模块结果、有效开始时间、时长、失败原因和同步偏差；重试始终重跑整个极限压测。
- 常规压测卡片、多选、“全选压测脚本”和 GPU → CPU/内存 → 磁盘串行语义保持不变。

## Capabilities

### New Capabilities

- `extreme-stress-validation`: 对 GPU 与 CPU/内存执行严格同步、原子化、无磁盘的极限稳定性压测。

### Modified Capabilities

- `stress-validation`: 保留常规压测套件语义，并定义极限压测的依赖准备、安全与结果规则。
- `task-results-observability`: 将极限压测作为单一历史任务呈现其总结果、模块明细与关联证据。
- `remote-task-execution`: 支持极限压测的原子取消、整体重试和重启恢复。

## Impact

- 前端任务下发页、任务历史页及任务展示工具。
- 压测套件 API、参数校验、远端任务编排、取消/重试/恢复与报告摘要解析。
- `backend/scripts/stress/` 中的 GPU、CPU/内存脚本和新增极限编排脚本；相关 README、架构和进度文档。
- 需要新增前后端、Shell 合约、同步/取消/恢复和报告展示回归测试。
