## Context

当前 `AppCritters.vue` 已使用单一 Vue 实例、CSS 动效、`MutationObserver` 与任务终态事件，提供右下角煤球及高风险 UI 静默。现有 `enter()` 会在每次路由切换后安排约 4.5 秒的自动回应，文案池规模小，且手动回应没有冷却；这与本变更的低频宠物独白和稳定角色感不一致。动机见 `proposal.md`。

## Goals / Non-Goals

**Goals:**

- 让煤球以可预测的低频独白和轻量动作呈现稳定的毒舌宠物人格。
- 保持任务失败、告警及危险 UI 的静默优先级，并避免路由切换造成连续气泡。
- 以可验证的文案分类和状态转换落实“吐槽机器、不吐槽人”的边界。

**Non-Goals:**

- 不创建聊天、命令执行、提示建议、养成、积分、持久化偏好或用户画像能力。
- 不调整任务、告警、权限或后端接口语义；不增加动画库或图片资源。

## Decisions

### 1. 用独立的自动独白调度维护 10--20 分钟随机间隔

首次安全挂载可安排一次独白；其后每次自动独白完成后重新抽取 10--20 分钟的等待时间。路由切换仅维持同一实例和视觉进入状态，不重置该调度。危险 UI、减少动效或卸载会取消待触发计时；危险 UI 结束后重新从安全状态安排，而不补发错过的文案。

选择独立调度而非复用当前短回应计时器，以区分气泡生命周期、短冷却和长期随机间隔。未选择固定周期：固定时间更容易被用户感知为打扰。

### 2. 将文案按触发来源与安全等级分池

文案至少分为自动独白、主动互动与成功收尾三类；每类仅包含针对机器、流程、等待、日志或煤球自身的吐槽。自动独白采用相对温和的语气，点击可使用更明显的运维梗；成功文案可嘴硬但要求操作者保留记录。危险状态不选择任何文案。

选择按来源分池，可确保高频自动场景不复用攻击性较强的点击语句。未选择从页面文本、停留时长或点击频率推断语气，避免隐私、误判和不可测行为。

### 3. 将宠物动作表示为短暂、可组合的视觉状态

在现有单实例状态上补充短暂的空闲张望、互动缩回与成功轻跳表现；动作完成后回到值守。动作和气泡均受同一危险状态与 `prefers-reduced-motion` 门控，且不改变煤球的固定安全位或键盘可访问性。

选择 CSS 状态类和现有 Vue 受控渲染，避免新依赖和资源下载。未选择持续复杂动画或多角色轮换，以防分散注意力及破坏全局唯一性。

### 4. 用统一回应冷却防止悬停、点击和事件刷屏

保留用户主动互动优先级，但为自动、成功和手动回应设定统一的短冷却；显式 `SUCCESS` 可以在合理冷却策略内占用一次回应。气泡无法安全显示时仍可执行极轻动作，但不保留不可见的气泡状态。

选择统一冷却而非允许手动悬停无限触发，以免鼠标经过右下角时重复刷屏。

## Risks / Trade-offs

- [随机独白仍可能出现在用户专注操作时] → 仅在安全页面、长随机间隔与统一冷却后触发，且文案保持短小。
- [页面未用标准危险选择器标记高风险区域] → 保留现有选择器，并要求相关 UI 继续使用 `data-soot-companion-danger` 标记。
- [CSS 动作在窄视口增加视觉负担] → 缩小视口沿用较小尺寸；气泡先做安全边界检查，无空间仅展示本体动作。
- [毒舌文案越界] → 以分类文案池和源码回归测试禁止操作者定向、失败玩笑及高风险场景发言。

## Migration Plan

1. 在本地以前端源码测试、生产构建和 Playwright 桌面/触屏用例验证状态、时序与安全静默。
2. 该变更无数据迁移、后端兼容或线上状态变更；若体验不符合预期，可回退 `AppCritters.vue` 及相关文案/测试/文档提交。
3. 代码合入后仍须经用户确认，才按项目既有部署流程发布；本 proposal 阶段不发布。
