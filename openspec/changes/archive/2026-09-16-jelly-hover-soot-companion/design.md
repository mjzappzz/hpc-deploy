## Context

当前 `AppCritters.vue` 将 `mouseenter`、`focus` 和 `click` 统一交给说话回应函数，导致第一次悬停后手动交互被 45 秒文案冷却拦截。现有煤球已具备固定安全位、单实例、任务终态和减少动效边界；本变更只调整悬停反馈的事件职责和视觉状态。动机见 `proposal.md`。

## Goals / Non-Goals

**Goals:**

- 让每次鼠标进入都可靠地产生果冻式 squash-and-stretch 反馈，并支持快速重复触发。
- 将悬停/聚焦的身体动作与点击吐槽、自动独白、成功反馈解耦。
- 保持不改布局、不新增依赖、尊重减少动效和危险 UI 静默边界。

**Non-Goals:**

- 不增加物理引擎、持久化状态、聊天能力、业务操作或新的后端事件。
- 不改变自动独白的 10--20 分钟调度、文案内容或任务终态语义。

## Decisions

### 1. 悬停事件只触发动作，点击事件才触发互动文案

将 `mouseenter` 与 `focus` 路径改为触发一次可重播的果冻动作；`click` 保留互动吐槽和短暂缩回。手动说话保留独立短冷却，动作不读取或修改该冷却时间。选择事件解耦而不是继续复用 `respond('manual')`，因为浏览器会在悬停后立即触发点击/聚焦链路，统一冷却会让用户误以为煤球失去交互。

### 2. 通过动画重启令牌可靠重播形变

每次进入递增一个动画令牌或切换一次 `is-jelly` 状态，在下一帧重新附加动画 class；这样即使上一次动画仍在运行，快速进出也会获得新的动画周期。动作只使用 `transform`，时间控制在约 220--320ms，形变序列为压扁、拉伸、轻微过冲、回弹。选择 CSS 而非物理库，以维持零新增依赖和低运行开销。

### 3. 视觉动作与现有状态机组合

新增 `jelly` 短暂状态或等价的动画令牌，不改变 `watching`、`responding`、`retracting` 和 `celebrating` 的业务含义。危险 UI 或减少动效时不触发形变；危险 UI 出现时立即清除气泡与待定文案，动作也应回到安全静止状态。

## Risks / Trade-offs

- [快速鼠标进出造成动作叠加或视觉过激] → 仅重启单一煤球的 transform 动画，不创建并行动画节点，限制幅度和时长。
- [键盘聚焦产生重复动作] → 使用浏览器事件路径的短重入保护，保证焦点与鼠标进入不会在同一交互瞬间重复播放两次。
- [触屏没有 hover 事件] → 点击/轻触继续触发缩回和互动反馈，减少动效偏好完全禁用形变。
- [动画 class 与呼吸动画争用 transform] → 将果冻形变作用在煤球本体或单独视觉层，并为 reduced-motion 提供更高优先级覆盖。

## Migration Plan

1. 先写悬停重播、快速进出、点击冷却与减少动效回归测试，再调整 `AppCritters.vue`。
2. 运行源码测试、生产构建和 Playwright 桌面/触屏回归，检查右下角边界、气泡、无障碍和控制台输出。
3. 使用既有 `redeploy_frontend_only.sh` 原子发布；若视觉不合适，将当前 release 链接切回上一目录并重新验证。
