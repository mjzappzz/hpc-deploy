## Context

仪表盘请求 `/api/dashboard/summary` 后分别回填服务器和任务字段，未回填同一响应中的 `storage` 字段。页面的容量告警以“状态不等于 `pass`”判断，因而初始 `unknown` 状态被错误解释为低空间。后端已提供所需统计与 `pass`、`warning`、`blocked` 状态，见本变更的 `runtime-data-lifecycle` delta spec。

## Goals / Non-Goals

**Goals:**

- 让仪表盘常驻展示与接口响应一致的控制器存储统计。
- 将容量告警限定为已确认的 `warning` 和 `blocked` 状态。
- 用回归测试锁定状态回填与未知状态不误报的行为。

**Non-Goals:**

- 不调整后端阈值、存储统计方式、自动清理机制或极限压测准入策略。
- 不新增后端 API 或持久化字段。
- 不在本变更中新增容量不可用时的独立提示组件。

## Decisions

### 回填完整的接口存储字段

在既有成功响应处理路径中将返回的 `storage` 覆盖到响应式页面状态。接口已包含该字段，直接使用可避免二次请求、字段重算和前后端阈值分叉。

备选方案是在前端重新计算容量状态或追加独立存储 API；两者都会复制后端决策或增加失败面，因此不采用。

### 明确枚举可告警状态

告警可见性仅匹配 `warning` 与 `blocked`；两者仍分别呈现警告与阻断级视觉语义。`pass` 显示容量统计但不呈现告警；`unknown` 显示容量统计暂不可用，不呈现默认零值，避免加载前或统计不可用时把占位值作为事实。

备选方案是继续使用“非 `pass` 即告警”并改变默认状态为 `pass`；这会掩盖真实的未知状态，因此不采用。

### 使用现有源码约束测试扩展回归

在 Dashboard 的现有 Node 源码约束测试中验证存储字段回填与显式容量状态判断，并执行前端构建。该变更不改变后端行为，无需调整后端测试。

## Risks / Trade-offs

- [接口缺少或返回异常 `storage`] → 保持现有加载失败处理；页面不把默认容量数据展示为低空间告警。
- [仅源码约束测试无法覆盖浏览器渲染] → 同时执行前端 build；如本地浏览器依赖可用，实施阶段可补充 Playwright 冒烟验证。

## Migration Plan

1. 合并前执行目标前端测试与 `npm run build`。
2. 按既有前端发布流程部署；无需数据迁移或服务重启以外的新操作。
3. 若出现回归，回退该前端变更即可恢复此前页面行为；后端 API、任务准入和运行数据不受影响。
