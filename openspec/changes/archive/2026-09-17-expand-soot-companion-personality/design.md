## Context

当前煤球由 `frontend/src/components/AppCritters.vue` 统一渲染，使用 Vue 响应式状态、CSS `transform` 动画、任务状态事件和 `MutationObserver` 识别危险 UI。现有实现已经具备悬停果冻、点击回应、低频自动独白、成功反馈、告警静默和减少动效降级能力。

## Goals / Non-Goals

**Goals:**

- 建立可扩展的煤球人格上下文，将页面、任务、设备、时间和连续点击统一转换为动作、文案和道具。
- 保证动作可重复播放、互不叠加，并遵守危险 UI、气泡避让、可访问性和低资源约束。
- 分四期交付：连续点击、设备拟态、页面道具、夜班与不确定性表达。
- 让每期可独立测试、发布和回滚。

**Non-Goals:**

- 不新增后端 API、轮询、WebSocket、数据库或用户行为上报。
- 不引入物理引擎、第三方动画库、视频、GIF 或大体积图片。
- 不把煤球动作当作精确监控指标、告警确认或业务控制入口。
- 不改变煤球固定右下安全位、单实例和减少动效策略。

## Decisions

### 1. 使用统一上下文和动作优先级

在组件内或相邻轻量模块维护 `CompanionContext`，输入已有路由、任务事件、危险 UI、时间段和可用设备状态，输出单一 `currentAction`、文案和道具。优先级固定为：危险/告警 > 任务终态 > 连续点击 > 设备/页面拟态 > 悬停果冻 > 待机。选择集中决策而不是在模板中堆叠条件，避免状态互相覆盖。

备选方案是为每种状态分别写独立 watcher；该方案初期简单，但容易产生重复 timer 和动画竞争，因此不采用。

### 2. 使用 token + timer 重播短动作

每个可重播动作使用递增 token、清理旧 timer、双 `requestAnimationFrame` 重置 class，再用 CSS `transform`/`opacity` 播放。连续点击计数使用 3 秒窗口，动作反馈不受说话冷却限制；说话只在允许时更新气泡。

备选方案是通过改变 Vue `key` 重建按钮；该方案会丢失焦点并增加 DOM 抖动，因此不采用。

### 3. 状态拟态只表达方向，不复制监控数据

设备和任务状态只映射为预定义动作、纸条或小道具，例如排队、繁忙、抖动和完成。若关键字段缺失，进入不确定性文案或静默。真实指标仍由原有页面展示，煤球不新增数据采集链路。

### 4. 视觉资产优先 CSS 和内联 SVG

小道具、纸条和夜班变化优先使用 CSS 伪元素或小型内联 SVG，保持零图片依赖和固定点击区域。所有动画限定在合成友好的 `transform`、`opacity`，并通过 `prefers-reduced-motion` 关闭。

### 5. 分期发布并保留回滚点

每期完成源代码测试、浏览器交互回归和生产构建后独立发布。前端继续使用现有原子静态发布脚本；问题出现时回指上一静态 release，不重启后端。

## Risks / Trade-offs

- [状态组合增多] -> 以优先级决策器限制同一时刻单一主动作，并为每个状态组合建立浏览器回归场景。
- [动作过于抢眼] -> 固定安全位、限制位移与持续时间，夜间降低幅度，告警时完全静默。
- [文案刷屏] -> 文案池去重、独立说话冷却和连续点击只在指定次数说话。
- [数据缺失导致误导] -> 缺失字段进入“装懂”或静默，不推断任务结果。
- [资源体积增加] -> 禁止大资源，引入前执行构建体积检查，优先 CSS/内联 SVG。
- [可访问性回归] -> 保持 button 语义、键盘激活、`role=status` 和减少动效测试。

## Migration Plan

1. 先实现并发布连续点击人格，确认单动画与现有悬停/点击行为兼容。
2. 在复用现有任务事件的基础上接入设备状态拟态。
3. 增加页面道具和日志纸条，并验证气泡/纸条不遮挡控件。
4. 最后启用夜班与不确定性表达，完成全量浏览器回归。
5. 任一期回滚时，将 `/var/www/.hpcdeploy-releases/current` 指向上一 release 并执行 `nginx -t`；不触碰后端任务。

## Open Questions

- 设备状态事件目前能提供到何种粒度，需在第 2 期开始前按实际事件字段选择可用映射；不改变本变更的安全边界或优先级。
